# auto-review code notes

`packages/experimental/auto-review/src/index.ts:apply`: when the integration unloaded under an active root (plugin removal or reload) each live Auto Session was switched to `danger-full-access`, whose approval policy is `never`. Auto's own state is Full access sandbox plus `ask`, and its prompts come only from the reviewer's `ask` decision, so once the reviewer was withdrawn later calls ran with no review and no approval, a permission change nobody chose. Unload now fails closed: each live Auto Session moves to the configured restrictive preset (`workspace-write` when configured, otherwise the first configured preset other than `danger-full-access`), which carries the `ask` approval policy and a non-full sandbox, and a warning is logged per Session. Only when the catalog configures nothing but full access does the migration still fall back to `danger-full-access`, because that is the only preset the operator offered. Reviews in flight are still cancelled and drained, and application shutdown still preserves the Session selection. Covered by `packages/experimental/auto-review/tests/auto-review.spec.ts` (restart, dispose and reinstall cases).
