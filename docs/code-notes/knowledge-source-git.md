# knowledge-source-git code notes

`packages/knowledge/knowledge-source-git/src/index.ts:resolveGitSource` (finding 90): the local-checkout path ran `git checkout --force` in the caller's own work tree, which silently discards conflicting staged or unstaged tracked edits. The local path now refuses a work tree with tracked changes (`git status --porcelain --untracked-files=no`), skips the checkout when `HEAD` already is the resolved commit (so the caller's branch stays attached), and otherwise runs a non-forced checkout, which Git itself refuses when it would overwrite local files. `--force` is kept only for the resolver-owned clone path: a `--no-checkout` clone has an empty index, so every file reads as deleted and a forced checkout is the normal way to populate it. The consequence is that `checkoutDir` must be resolver-owned; the README says so. Resolution of a local checkout to a different commit still moves its `HEAD`; an isolated per-commit worktree was not built.

`packages/knowledge/knowledge-source-git/src/index.ts:listSourceFiles` (finding 91): the line-oriented `git ls-files` output quotes or escapes unusual names (non-ASCII, tab, newline) and the per-line `.trim()` removed valid leading and trailing spaces, so a returned path could differ from the tracked one. It now runs `git ls-files -z` and splits the raw stdout on NUL, so each path is returned byte for byte. It reads the raw `git()` result instead of `gitOrThrow`, whose `.trim()` would strip leading spaces from the first path.

`packages/knowledge/knowledge-source-git/src/index.ts:resolveGitSource` (finding 92): the local-checkout fetch result was ignored, so a failing fetch of a configured remote left an old `refs/remotes/origin/<branch>` ref to be resolved as if it were current. A checkout with no remote (`git remote` prints nothing) still skips the fetch, but a checkout with a remote now fails the sync with the fetch error. Remote clones already used `gitOrThrow` for the fetch.

`packages/knowledge/knowledge-source-git/src/index.ts:resolveGitSource` (finding 94): a relative local `repo` or relative `checkoutDir` was returned unchanged as `root`, so a consumer in another working directory resolved it differently. `root` is now `path.resolve`d (not `realpath`, so symlinked or short Windows temp names are kept as given). Only `./`, `../`, `/` and drive-letter forms are local paths; a bare `dir/name` is GitHub shorthand, which the README now states.
