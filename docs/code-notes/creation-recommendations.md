# creation-recommendations code notes

## packages/experimental/creation-recommendations/src/index.ts:PersonalizedPages::generate (issue 197)

The Creator run had no deadline, so a stalled or looping child kept its subagent capacity slot and model cost until the user cancelled or the Session closed. `generate` now arms a `CREATOR_TIMEOUT_MS` timer (60 minutes) before the activation starts and aborts the job controller with reason `timeout`. The existing abort path disposes the activation and awaits that disposal in the `finally` around `activation.result` before the outer `catch` records anything, so the receipt moves to `interrupted` (a retryable open phase) only after cleanup is confirmed; a failing disposal still rethrows into the same catch. The timer is cleared as soon as the Creator finished, so a slow validation, copy or Plugin Manager installation is never aborted by it (installation is Plugin Manager's own accepted work). The limit is a module constant, not a Config field: a new field needs generated catalog JSDoc that the comment guard rejects, and the lead regenerates catalogs. Only elapsed time is limited; there is no token or tool-call budget because the subagent service exposes none to this plugin.

## packages/experimental/creation-recommendations/src/generated-bundle.ts:validateGeneratedBundle (issue 198)

The validator read the manifest and patch whole and walked the tree without budgets, and the copy had none either, so an oversized Creator output could exhaust memory or profile disk before installation. `validateGeneratedBundle` takes `BundleLimits` (default `BUNDLE_LIMITS`): manifest and patch are size-checked with `stat` before `readFile`, and `validateTree` (which replaced `validateLinks`) streams each directory with `opendir` and throws as soon as entry count, depth, a single file's size or the running byte total is exceeded. Symlinks count as entries and are not followed; their targets are counted through the files they name. Because the source is validated before `cp`, the copy is bounded by the same budget. The copy goes to `<directory>.staging`, is validated again, then renamed, and the staging directory is removed on any failure, so a failed or cancelled copy never leaves a half-written profile copy at the real path; the source tree is never deleted. Limits are module constants rather than config for the same catalog reason as the timeout. Residual: `cp` itself cannot be aborted, and a source modified during the copy is only caught by the second validation, after the copy finished.
