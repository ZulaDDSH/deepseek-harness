`packages/session/session-stats/src/projection.ts:sessionStatsProjectionDefinition` times decode from the first token of the final assistant message's own stream, not from the step's first token: first-token latency (`ttftMs`) keeps the first attempt's boundary across `llm/retry`, but the final message's output-token count belongs to the final attempt only, so measuring decode from an earlier failed attempt put the failed attempt and the retry wait into the denominator and understated tokens per second (finding 326). A step whose final stream carries no token accrues neither decode time nor decode tokens, so a rate is never built from mismatched intervals. Failed attempts contribute no decode tokens, so the figure is the final attempt's decode rate.
