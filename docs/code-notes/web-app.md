# web-app code notes

`packages/bundle/web-app/src/memorix.ts:apply`: Memorix 1.9.10 can upgrade its database in place on first open, and a failed pre-upgrade copy used to be logged while the launch recipe was still provided, so the server then upgraded the only copy. `apply` now withholds `memorixLaunch` when `backupExistingDatabase` throws, so the `memory-memorix` row reports Memorix unavailable and the rest of Web starts. `backupExistingDatabase` also treats an existing backup that is not a non-empty regular file, or a copy whose size differs from its source after copying (a concurrent writer), as a failure. The copy is still a file copy, not SQLite's online backup, so a writer that changes the database between the two size checks is not detected; the README states that.
