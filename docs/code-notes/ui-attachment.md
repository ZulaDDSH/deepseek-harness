# ui-attachment code notes

`packages/client/ui-attachment/src/client/drop-events.ts:installDocumentDropEvents`: every mounted attachment view installs document-level drop listeners, so a parent conversation and a continuable subagent conversation both added one external drop to their drafts (finding 29). The listeners now register in a module-level set and `resolveDropOwner` picks one owner per event, memoised per event: the accepting view whose `[data-composer-card]` contains the drop target, else (external `Files` only) the first accepting view in document order. Internal file-drag tokens have no fallback because they only count inside a composer card. `dragover` uses the same owner for `dropEffect`, so a disabled view cannot cancel the drop for an accepting one. The anchor is a hidden `<span>` rendered by `ComposerAttachments` because the component otherwise renders a fragment and an empty rail has no element. The drag overlay is still shown by every mounted view; only the drop is routed.

`packages/client/ui-attachment/src/client/drop-events.ts:resolveDropOwner`: picks the one view that handles a drag event, memoised in a `WeakMap` keyed by the event so every document listener agrees. Owner order is: accepting view whose composer card contains the event target, then (external `Files` only) the first accepting view in document order, else none (`dragover` reports `dropEffect: 'none'`).
