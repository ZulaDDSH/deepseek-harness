`packages/experimental/session-title-all-prompts-llm/src/index.ts:frameWithinBudget` keeps the title request inside `maxInputBytes` by sending the newest contiguous suffix of eligible human messages that fits, instead of serializing the whole aggregate and letting the shared executor reject the oversized input (finding 325). Before this, once the cumulative eligible history passed the cap every later revision and refresh failed and the title stopped updating, and each attempt stringified the entire history first. The window is chosen newest-first with a per-message byte count, stops at the first message that does not fit, and rejects a message cheaply by text length before stringifying it (JSON bytes are never fewer than the UTF-16 unit count), so serialization work is bounded by the budget plus one message rather than by session length.
`packages/experimental/session-title-all-prompts-llm/src/index.ts:frameWithinBudget` returns only the included messages' seqs as the result attribution, so `messageSeqs` stays an exact ordered subset of the service snapshot, and when older messages were left out the frame adds `omittedEarlierMessages` with their count so the model and the logged request both show that context was omitted. The older context is represented only by `currentTitle`; no summary of omitted messages is made. When even the newest message plus the frame overhead exceeds the budget, the function still frames that one message so the executor rejects it with its normal `maxInputBytes` error and the old title is kept, which preserves the documented oversized-prompt failure.
`packages/session/session-title/src/index.ts:collectSessionTitleMessages` is deliberately unchanged: the service still scans the log and joins the text of every eligible message through the scheduled revision on each generation, so the scan stays linear in history length. Bounding that scan needs an incremental or retained projection owned by the service and is left as a recorded limit of finding 325.
