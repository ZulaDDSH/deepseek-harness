# llm-deepseek code notes

`packages/llm/llm-deepseek/src/file-store.ts:DeepSeekFileStore::reclaimOldestOwned` (finding 203): quota recovery and `releaseAll` used to treat any remote file whose name started with `dsh-` as harness-owned, so another client sharing the provider account could lose prefix-colliding files. Ownership is now positive: `DeepSeekUploadIndex` persists an `owned` ledger (scope, provider file id, expiry) written by `DeepSeekFileStore::uploadOnce` as soon as the provider returns an id, before the response is validated or committed, and `reclaimOldestOwned` deletes only listed files whose id is in the ledger or is a live index mapping for the same scope. The filename prefix is no longer evidence. Ledger entries leave when the file is deleted (reclaim, release, duplicate cleanup), when the scope is cleared, and when expired (pruned on write; the provider deletes expired files itself). `owned` is optional in the stored JSON, so older index files load unchanged. Limit: uploads made by earlier versions that are neither live mappings nor in the ledger are never auto-deleted; they expire with their requested lifetime or the user removes them.

`packages/llm/llm-deepseek/src/bounded-body.ts:readBoundedText` (finding 204): Messages error bodies (`response.text()`) and Files responses (`response.json()`) were buffered without a byte limit, so a faulty gateway could stream unbounded data inside the idle timeout. All of them now go through `readBoundedText`, which rejects a larger declared `content-length` before reading, counts streamed bytes, cancels the body at the limit, and reports `truncated`. Messages error bodies (`adapter.ts:DeepSeekAdapter`) and Files error bodies (`files-api.ts:DeepSeekFilesClient::request`) keep a 64 KiB diagnostic excerpt: a truncated body fails JSON parsing, so the HTTP status stays authoritative. Successful Files responses (`files-api.ts:responseJson`) allow 8 MiB (a 1000-entry list page is a few hundred KiB) and fail with `INVALID_RESPONSE` on overflow. Streamed Messages success bodies are SSE and not buffered, so they are out of scope.
