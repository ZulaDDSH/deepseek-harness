# frontend-static code notes

`packages/host/frontend-static/src/index.ts:readInsideRoot`: the traversal fence compared the normalized pathname with the dist root, but `readFile` follows symbolic links and junctions, so a link inside the dist tree served any file the Host user could read (finding 161). Policy: links inside the dist tree are allowed only while they resolve to a place inside the real dist root; anything resolving outside is answered 403, the same as lexical traversal. The check opens the file first, resolves `realpath` of the path afterwards, requires the real path to be the real root or below it, and requires the opened handle to be the same file (device and inode) as the resolved path, so a link swapped in between the lexical check and the read either fails the comparison or is read through the handle that was already verified. The residual window is a swap between the `open` and the `realpath`, which the inode comparison catches unless the replacement is a hard link to the same inode. Windows reports file ids through the same `bigint` stat; a file system that reports inode 0 for everything would reduce this to the realpath check alone. Only non-index assets are covered: the configured `distIndex` path is operator-supplied and is read as before.
