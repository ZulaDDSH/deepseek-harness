# message-feedback code notes

`packages/feedback/message-feedback/src/index.ts:MessageFeedbackService.put`: a per-message rating could not be kept on the device, so a note typed into the rating dialog was released to the telemetry collector with the conversation prefix, while `/feedback --local` could keep a remark local. `MessageFeedbackPutRequest.localOnly` now travels on the `feedback/message-put` event (event level, not on the stored item, so the item shape and its version token are unchanged) and the telemetry backend treats such an event as a non-authorizing record. The field is written only when `true`; an absent field is the exported form, so existing logs read the same. `putSchema` accepts the optional boolean, so replaying a log never rejects it. A put that matches the stored rating, note and category stays a no-op and appends no event, whatever `localOnly` says; the stored item does not remember its earlier visibility, so re-submitting an unchanged rating cannot switch an already exported or an already local rating. Covered by `packages/feedback/message-feedback/tests/message-feedback.spec.ts` (local-only cases).

`packages/feedback/message-feedback/src/index.ts:MessageFeedbackService.delete`: withdrawing a rating is itself an export trigger, so the delete request carries the same optional `localOnly` and the `feedback/message-delete` event records it only when `true`; `deleteSchema` accepts it. The flag is not inferred from how the rating was put: the human chooses at the withdrawal confirmation. Covered by the same spec.
