# agent-default-model code notes

`packages/core/agent-default-model/src/index.ts:AgentDefaultModelConfig.saveInitialSelection` (finding 221): account sign-in used to replace the default whenever no provider API key was configured, so a default the user had chosen (a keyless local provider, an OAuth provider, another account model) was overwritten on every later sign-in, and the read of the catalog before the write let a deliberate selection made in between be overwritten by the older initialization. The service now treats the default as unset only while the active profile patch holds no `config` override for this entry (`ConfigEditor.configuration()` override layer); `saveSelection` is the only writer of that override, and the bundled provider and model are the untouched bootstrap default. A selection that was submitted but not yet written is caught by `submitted`, a counter bumped synchronously at submission by `saveSelection`; `saveInitialSelection` compares it in the same synchronous step that enqueues its own write, so a concurrent explicit save always wins. Without a configuration editor there is no override layer to read, the default is treated as unset and the write is the documented no-op.
