# workspace code notes

`packages/workspace/workspace/src/index.ts:WorkspaceRegistry::archiveSession`: an ordinary (no `stopActivity`) archive asked the `workspace/session-activity` waterfall once and then wrote the archive, so a turn admitted between the answer and the durable write ran its already-admitted steps while the Session was hidden (issues.md finding 50). The registry cannot serialize turn admission, which belongs to the Agent loop in `packages/core/agent-loop/src/agent.ts` (phase `running` is set before the first `agent/pre-step`, and the `turn` provider in `packages/core/agent/src/archive-admission.ts` reports a running Agent). The activity question is therefore asked again after the durable write: from that write on, the archived set gates every new `agent/pre-step` (`packages/api/session-controller/src/archived-session-gate.ts`), so any turn the second answer shows was admitted before the write. A non-empty second answer restores the exact previous state with `setState(state)` (still inside the registry's operation chain, so no other write interleaves) and rejects with `WorkspaceActiveSessionError`; the caller can retry or pass `stopActivity`. The first question stays as the cheap refusal that writes nothing. A window remains in which a step admitted before the write finishes while the second answer sees no activity; that work already ended, so nothing runs out of view. No `session-controller` edit is needed. Covered by the "rolls back an archive when a turn starts between the activity check and the write" test in `packages/workspace/workspace/tests/workspace.spec.ts`.
