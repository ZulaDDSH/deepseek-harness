# workspace-files code notes

`packages/api/workspace-files/src/index.ts:Config.confineReads` and `WorkspaceFiles::locateFile`: `read`, `readBytes` and `stat` resolve absolute paths through the composed filesystem's read authority, so a principal granted them on one Session can read any Host file the process can read (issues.md finding 20). Remote methods receive only the Session-derived scope, not the caller's principal, so the service cannot tell an owner from a grantee. `confineReads` is the deployment switch and defaults to true: `locateFile` resolves the path and requires `fs.contains(workspaceRoot, target)` or containment in one of `Config.readRoots`, resolved per call through `fs.resolve` by `WorkspaceFiles::inReadRoot` (the same containment `list` uses, which follows links through `fs.resolve`), refusing with `workspace-file/outside-workspace`; the `baseFile` hop in `readBytes` and a file target of `changes` take the same gate because both go through `locateFile` / `WorkspaceChangeFeed::follow`. The default was first left `false` because the owner UI previews files outside the workspace; the owner decided the hole must be closed by default, so the default is `true` and the legitimate outside reads are an explicit allowlist: `readRoots` for deployment-listed directories, and `WorkspaceFileScope.trusted` for Host code that already authorized a path from a Host-held record (`packages/client/ui-deliverables/src/present-open.ts` builds such a scope for its native-open `stat` calls). `trusted` is never set by the Typert lookup that produces the scope of a Remote call, so a client cannot supply it. Setting `confineReads: false` restores the old behavior. The change feed takes the same admission through `ChangeFollower::follow`'s `admitsOutside` callback. Covered by `packages/api/workspace-files/tests/confine.spec.ts`.

`packages/api/workspace-files/src/changes.ts:ChangeFollower`: every instrumented `fs/observed` emission was appended to every follower's queue before the target filter ran, and the queue was unbounded, so one stalled subscriber retained all filesystem activity (finding 45). Every matching observation produces the same action (re-stat the target and yield its current metadata), so the queue is replaced by one dirty flag once the target key is known. Before the target resolves, observed target keys are kept in a set capped at `PRE_TARGET_LIMIT`; overflowing it marks the follower dirty, which costs at most one extra re-stat frame. Covered by `packages/api/workspace-files/tests/changes.spec.ts` ("coalesces ..." and "ignores unrelated ...").
