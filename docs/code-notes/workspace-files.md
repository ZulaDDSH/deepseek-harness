# workspace-files code notes

`packages/api/workspace-files/src/index.ts:Config.confineReads` and `WorkspaceFiles::locateFile`: `read`, `readBytes` and `stat` resolve absolute paths through the composed filesystem's read authority, so a non-owner principal granted them on one Session (a share viewer or another restricted principal admitted by a Remote Access policy) can read any Host file the process can read (issues.md finding 20). The owner's Web client legitimately previews files outside the workspace (home documents, office-kit and temporary outputs), so confinement must not apply to it. `WorkspaceFiles::scoped` decides per call: it is true when `Config.confineReads` is on, the `WorkspaceFileScope.trusted` flag is not set, and `principalOf(this.ctx.invocation)` from `@deepseek-ai/dsh-typert-protocol` is defined. `principalOf` reads `ctx.invocation.peer.principal`, which in-process Host code fixes when it creates the Peer and no wire field can set, and returns undefined for the owner and for trusted in-process code outside a Remote call, so those keep their current reach and a client cannot opt itself out. For a scoped caller `locateFile` resolves the path and requires `fs.contains(workspaceRoot, target)` or containment in one of `Config.readRoots`, resolved per call through `fs.resolve` by `WorkspaceFiles::inReadRoot` (the same containment `list` uses), refusing with `workspace-file/outside-workspace`; the `baseFile` hop in `readBytes` and a file target of `changes` take the same gate because both go through `locateFile` / `WorkspaceChangeFeed::follow` (its `admitsOutside` callback). `confineReads` defaults to true so the scoped case is closed by default; `false` restores unconfined reads for scoped principals. `readRoots` is the operator allowlist for scoped principals. `trusted` stays for Host code that calls the service with a Host-built scope while a scoped caller's invocation is in force (`packages/client/ui-deliverables/src/present-open.ts` native-open `stat` calls on a Host-held record); the scope a Remote call receives never carries it. Covered by `packages/api/workspace-files/tests/confine.spec.ts`.

`packages/api/workspace-files/src/changes.ts:ChangeFollower`: every instrumented `fs/observed` emission was appended to every follower's queue before the target filter ran, and the queue was unbounded, so one stalled subscriber retained all filesystem activity (finding 45). Every matching observation produces the same action (re-stat the target and yield its current metadata), so the queue is replaced by one dirty flag once the target key is known. Before the target resolves, observed target keys are kept in a set capped at `PRE_TARGET_LIMIT`; overflowing it marks the follower dirty, which costs at most one extra re-stat frame. Covered by `packages/api/workspace-files/tests/changes.spec.ts` ("coalesces ..." and "ignores unrelated ...").
