# file-reference-local code notes

`packages/context/file-reference-local/src/search.ts:WorkspaceFileSearch.indexFor` (finding 157): the bare-query index was invalidated only by a `tool/result` in the owning agent's session, so files created, renamed or removed by an editor or another agent stayed invisible (or offered) until that agent next ran a tool. A settled index now also counts as stale once it is older than `REVALIDATE_AFTER_MS` (5 seconds); the existing stale-while-revalidate path then answers from the old entries immediately and rebuilds in the background, so a keystroke never waits on a traversal. There is no filesystem watcher: an external change appears on the first bare query after the window plus the background rebuild, i.e. one query later.

`packages/context/file-reference/src/grammar.ts:formatFileMention` (finding 239): the sent-message rules in `packages/client/ui-reference/src/client/user-text-rules.ts:nextPath` strip `.,;:!?` and their full-width forms from the end of an unquoted `@` token as sentence punctuation, so a selected file `report!` inserted as `@report!` was rendered and opened as `report`. A path whose last character is one of those characters is now inserted in the quoted `@"path"` form, which `nextPath` never strips and `activeAtToken` already reads. The character set must stay in step with `nextPath` and `TRAILING_PUNCTUATION` in `packages/client/ui-conversation/src/client/input/decorations.ts`. Directories end in `/` and need no quoting.

`packages/context/file-reference-local/src/search.ts:readEntries` (finding 235): directories were read whole with `readdir` and sorted before either the index cap or the result cap applied, so one huge directory cost memory and a synchronous sort far beyond both limits, and cancellation could not interrupt it. `readEntries` now streams the directory with `opendir`, stops after `maxEntries` usable entries, checks the abort signal between entries, and only then sorts the retained prefix. A directory with at most `maxEntries` entries behaves exactly as before. A larger directory is truncated to the first `maxEntries` entries in filesystem order, so its ranking is no longer complete or deterministic; the candidate contract carries no truncation flag, so this is a documented limit rather than a reported one. Entries are counted after filtering.

`packages/context/file-reference-local/src/search.ts:WorkspaceFileSearch.scanWorkspace` (finding 236): hidden files and directories (a name starting with `.`) used to share the `maxEntries` budget in plain breadth-first order, so a large `.cache` sorted before `src` could fill the index before `src` was visited, although a bare query never shows hidden paths. The scan now indexes visible paths first and defers hidden-named entries, traversing hidden subtrees only with whatever budget the visible tree leaves, so a hidden tree can no longer starve visible completion; explicit hidden queries (`.name`, `/.`) still find hidden paths that fit. An index truncated by the cap is still not reported to the caller.

`packages/context/file-reference-local/src/search.ts:readEntries` (finding 240): a POSIX filename containing a literal backslash cannot be addressed, because `sessionFileAddress` and `fileAddressFor` in `packages/util/workspace-path` rewrite every backslash to `/` (needed for Windows separators), so the offered `@a\b.txt` opened `a/b.txt`. Carrying a Host path flavor through discovery and addresses is a protocol change, so the safe default is to not offer such names: `readEntries` skips any entry whose name contains a backslash (Windows names cannot contain one). Typing a backslash in a query still means a directory separator. Decision for the lead: a path-flavor field on the address would let these files be offered again.
