# lsp-stdio code notes

`packages/lsp/lsp-stdio/src/instance.ts:LspInstance.initialize` (finding 40): `initialize.processId` stays `null` by default because `ctx.subprocess` may run the server on another machine or in another PID namespace, where the host PID would name an unrelated process (or none) and make the server exit or monitor the wrong thing. The seam does not report whether the provider shares the host's PID namespace, so the host cannot detect this. `LspLocalServerConfig.reportHostProcessId` (default false) lets a deployment that knows its provider is same-host opt in; the server then exits on its own when the host process disappears after a hard kill. Remote and separate-namespace providers keep `null`; a provider-owned process lifetime (PDEATHSIG, Job object) needs a subprocess-seam change outside this package.
