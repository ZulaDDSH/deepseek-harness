# subagent code notes

## packages/subagent/subagent/src/manager.ts:SubagentManager::deliverToMember (issue 33)

Inbox admission is synchronous and in memory; the JSONL backend batches the resulting `inbox` event, so `send_message` and host prompts used to return a message id before the insertion was on disk. A crash in that window lost an accepted instruction with no replay.

Fix: after the per-child lock is released, the accepted target's Session is flushed (`ctx.sessions.flush`) before the id is returned. The flush runs outside the lock so other deliveries are not serialized behind storage latency, and it never un-accepts: the message is already in the live inbox and will run. A flush failure is logged and the id is still returned, because retrying would duplicate a message that is already queued; the id is the stable identity of the accepted message. Memory-only sessions flush as a no-op.

## packages/subagent/subagent/src/manager.ts:SubagentManager::interrupt (issue 60)

The README's "wake gap during cancellation convergence" limitation was stale: `interrupt` cancels with `keepInbox`, delivery uses the waking `steer`/`followup`, and `Agent.send` classifies a waking send after abort as next-turn input, latches the wake and replays it when the aborted driver converges. The regression `runs a send_message accepted between interrupt and idle once the child converges` in `tests/continuation.spec.ts` passes on unmodified code, confirming the finding. The distinct driver-retirement race (input landing after the final inbox check) is closed in `packages/core/agent-loop/src/agent.ts:Agent::kick` (issue 24), so no limitation remains.

`packages/subagent/subagent/src/out-of-process.ts:assertExternalCwdWithinParentWorkspace` (finding 178): an external child (Codex, Claude Code, ACP) receives its own native workspace from the cwd the provider is started in, but the sandbox clamp passes only the parent's mode, so a `workspace-write` parent could name any enterable directory and make it the child's writable root. `SubagentManager.startExternalNamed` now checks the resolved cwd after `resolveDirectory` and before the provider starts. Under any parent mode other than `danger-full-access` (or `read-only`/`workspace-write` resolved by `ctx.sandboxPolicy`), the physical (realpath) cwd must be inside the physical parent workspace root or one of its `additionalWritableRoots`; relative `..` traversal is caught because the path is resolved first and symlinks because both sides are realpathed. Without a composed `sandboxPolicy` the check is skipped, as for the Codex clamp. A cwd that does not yet exist is compared lexically and left to `assertUsableCwd`. In-process children are not affected: their Session keeps the parent's immutable header cwd as the workspace root. Limit: the check is one-time at start; a child that is a native agent can still choose its own paths inside the granted root.

`packages/subagent/subagent-acp/src/index.ts:AcpProvider.start` (finding 177): the ACP child is an ordinary host-account process; `permission: reject` only answers prompts the child chooses to send, and a working directory is not a filesystem boundary. The provider cannot attest or enforce the parent's sandbox, so start now refuses with `PARENT_SANDBOX_MISMATCH` unless the parent session resolves to `danger-full-access` or no `sandboxPolicy` is composed. The `allowRestrictedParent` config flag is an explicit operator attestation that the command is contained externally (container, OS sandbox); it defaults to false.

`packages/subagent/subagent/src/manager.ts:SubagentManager::materializeTracked` (finding 179): an external child that stays alive but never answers its initialize or session-creation request kept the reserved tree slot and the waiting tool call until the caller cancelled. The external branch now races the provider start against a startup deadline (`EXTERNAL_STARTUP_TIMEOUT_MS`, five minutes, module private). On expiry the startup signal is aborted with a `STARTUP_TIMEOUT` `SubagentError`, which the provider's own cancellation path uses to kill and reap the child, the failure message names the stage that was pending (`provider start: initialize and session creation`), and the existing catch in `materialize` releases the slot. A provider that ignores the signal cannot hold the slot either: the race rejects at the deadline and a run that resolves later is disposed instead of leaking. The manager cannot tell initialize from session creation, so the stage is the provider handshake as a whole; a provider's own error text may be finer. The deadline is not configurable because a new config field would need the generated catalog; Codex's optional run timeout still starts only after the handshake.

packages/subagent/subagent/src/catalog.ts:subagentCatalogProjectionDefinition (finding 346): the catalog state is a `ChunkedList` whose checkpoint shape changed from a linked chain of 64-fact nodes to bounded-height blocks (see `docs/code-notes/chunked-list.md`, `packages/util/chunked-list/src/index.ts:appendChunkedList`), so `stateVersion` moved from 6 to 7. A cached version-6 row is no longer read; the projection cache treats a version mismatch as absent and the catalog is folded again from the parent's `subagent/catalog` events, which are unchanged and remain the only source of truth, so no child record is lost and a session's first load after the upgrade pays one replay.
