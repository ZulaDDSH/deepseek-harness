# ui-chat code notes

`packages/client/ui-chat/src/client/chat/use-known-outline.ts:useKnownOutline` (finding 163): the host `turnOutline` projection holds only the newest 500 turns and slides as turns start, so the rail would lose both turns older than the window and turns that fall out of it after older pages loaded. The hook therefore accumulates every entry it has ever seen (projection value and paged older entries) per Session and hands the whole set to `mergeTurnRailItems` as the outline; the current projection value overwrites same-turn entries. The page-back trigger is the loaded history window: once its first seq is at or below the oldest known entry's `turn/start` seq (or the cursor the last page returned), the next older page is requested, so the rail grows as history pages back and a rail jump (`loadThrough`) onto an old mark needs no extra request. A failed call is not retried until the window head moves; an exhausted page (`hasMore` false) ends paging for the Session. Responses that return after the Session changed are dropped.

`packages/client/ui-chat/src/client/apply.ts:loadOutline` (finding 163): the paged read is injected as a Remote call on `ctx.remote.session.outline`, addressed like the Session's own history (`snapshot.subagent.address` for a child). A Remote error resolves to null; it is a display feature and never surfaces an error.

`packages/client/ui-chat/src/client/chat/turn-rail-items.ts:absorbOutline` (finding 163): shared narrowing for the projection value and for paged older entries; both are wire data, so the same `outlineEntry` guard decides what may enter the known set. `oldestKnownSeq` is the page-back target the hook compares the loaded window head against.

`packages/client/ui-chat/src/client/chat/ApprovalCommand.tsx:describeApproval` (finding 301): the approval preview keeps its specialised primary text (command, terminal text, write or edit excerpt, code, pretty JSON) and now also lists every other argument as a `key: value` row, so a `workdir`, `replace_all`, terminal `sessionId` or `submit` flag is visible next to the command it changes. Each row value is the JSON encoding of the argument clipped at 200 characters. When any line clip, row clip or the 4096 character JSON clip applies, `full` carries the complete pretty-printed arguments and the component offers them in a native `details` element, so clipped content has an explicit expansion path. Terminal input with empty `text` no longer returns nothing; it falls through to the generic JSON preview so its `sessionId` and `submit` stay visible. `approvalDetail` still returns only the primary text.

`packages/client/ui-chat/src/client/chat/ApprovalCommand.tsx:ApprovalCommand` (finding 302): the component reports through the optional `onAvailability` owner prop whether a correlated call with parsable object arguments was found, so the approval card can tell a missing or not-yet-started call from a legitimately argument-free one (an empty object is available and renders nothing). The selector returns the raw argument string, not the described object, because a fresh object per snapshot would defeat the selector's change detection.

`packages/client/ui-chat/src/client/chat/ApprovalCommand.tsx:ApprovalDetailView` (finding 301): `preview` is the primary text, `rest` the other argument rows, and `full` the unclipped pretty-printed arguments, present only when a line clip, a row clip or the JSON clip applied.
