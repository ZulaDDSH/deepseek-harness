# cli code notes

`apps/cli/src/process-shutdown.ts:createProcessShutdown`: a failed or timed-out disposal used to force-exit with the code the caller asked for, so normal completion and SIGTERM (both request 0) reported success to a supervisor although persistence or child cleanup had not finished (finding 101). Both outcomes now write one line to stderr (`report`, replaceable by tests) and exit with `CLEANUP_INCOMPLETE_EXIT_CODE` (1) when the requested code was 0; a nonzero requested code (a failing command, SIGINT's 130) is kept because it already signals failure. A second signal still forces an immediate exit with that signal's own code and writes no diagnostic: it is the operator's explicit override, and a user who interrupts twice asked to stop waiting. The unchanged normal path (disposal resolves, `complete(code)`) still exits with the requested code.
