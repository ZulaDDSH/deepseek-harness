# command-feedback code notes

`packages/feedback/command-feedback/src/index.ts:recordFeedback`: `FeedbackRecord.localOnly` marks a remark recorded for the Session log only. With session telemetry in its default feedback-gated mode every `feedback/record` otherwise releases the conversation prefix to the collector, and a user who only wanted to leave a note had no way to decline that. The `/feedback --local <text>` form and `sessionFeedback.record({ localOnly: true })` write `localOnly: true`; the OTel backend does not treat such an event as authorization and blanks it from later exports (see `docs/code-notes/session-telemetry-otel.md`). The acknowledgement of a local remark states that it was not shared. A per-message rating has no local-only form: its `feedback/message-put` and `feedback/message-delete` payloads have no such field, so rating, editing and withdrawing a rating still authorize the export; the client dialog and the withdrawal confirmation state this before the action.

`packages/feedback/command-feedback/src/index.ts:SessionFeedbackService.sharing`: the feedback dialog and the rating-withdrawal confirmation told the user "while telemetry is enabled" because the browser could not learn the Host's live sharing policy. The `sessionFeedback.sharing` Remote returns `{ sharing, destination? }`: `sharing` is the mounted backend's `SessionTelemetryBackend.sharing` (`full`, `feedback-only`, `disabled`) or `none` when no backend is mounted, and `destination` is the backend's published origin. The Remote lives on this existing service rather than a new `sessionTelemetry` one because this package already owns the feedback Remote namespace and reads `ctx.get('sessionTelemetry')` for the `/feedback` notice, and a new namespace would need its own generated Remote contract. It takes no argument, carries no Session data, is classified `owner-only` in `packages/experimental/liveshare/src/endpoint-classification.ts` so a LiveShare viewer cannot read the Host's collector, and is read-only. Covered by `packages/feedback/command-feedback/tests/command-feedback.spec.ts` (sharing cases for telemetry on, feedback-only, disabled and absent).
