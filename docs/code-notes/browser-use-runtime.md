# browser-use-runtime code notes

## packages/experimental/browser-use-runtime/src/index.ts:SessionResources::closeEntry (issue 329)

The first close attempt and the first disposal attempt were cached for the life of the manager even when they rejected, so a transient close failure could never be retried and an exclusive attachment held by a closed Session stayed reserved forever. A rejected attempt now clears its cached promise (only if it is still the cached one), so concurrent callers share one in-flight attempt and the next caller starts a fresh one. The entry stays registered until `resource.close()` has resolved, so ownership is never released on a failed or unverified close. Retries are started from the `BROWSER_LOCKED` path of `SessionResources::entry`, and only for entries whose owner is already disposed, so a live owner's browser is never closed by another Session's request; the request that triggered the retry still fails with `BROWSER_LOCKED`, and a later request succeeds once the retry has verified the close. `SessionResources::dispose` keeps its admission gate in a separate `stopped` flag, so a rejected disposal can be repeated while the manager stays closed to new owners.

## packages/experimental/browser-use-runtime/src/mcp.ts:rejectSecretBearingEndpoint (issue 330)

An attach endpoint was passed to the MCP server as a command-line argument, which other local accounts and process monitors can read, so a bearer token in the URL was disclosed. The pinned Playwright server reads `PLAYWRIGHT_MCP_CDP_ENDPOINT` (playwright-core `coreBundle.js`, the `options.cdpEndpoint = envToString(e.PLAYWRIGHT_MCP_CDP_ENDPOINT)` line), so `packages/experimental/browser-use-playwright-mcp/src/index.ts:apply` sends the endpoint through the child environment and keeps it out of the arguments. The pinned Chrome DevTools server has no environment variable for `--browser-url` or `--ws-endpoint`, so `packages/experimental/browser-use-chrome-devtools-mcp/src/index.ts:apply` calls `rejectSecretBearingEndpoint`, which refuses a URL carrying userinfo, a query string or a fragment. A secret kept in the path, such as a token segment, cannot be told apart from the `/devtools/browser/<id>` path that a WebSocket endpoint needs, so it is not rejected and stays visible in the arguments for that provider; the error text never echoes the URL.
