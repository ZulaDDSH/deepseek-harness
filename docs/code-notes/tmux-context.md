# tmux-context code notes

## A known-to-unknown location transition is recorded, and a recovery re-publishes (finding 298)

- `packages/context/tmux-context/src/index.ts:queryTmuxLocation` - a missing shell, failed query, timeout or tty mismatch used to return without adding a message, so a session resumed outside its old pane kept the old reading as the latest durable location and nothing told the model it no longer applied. The query now returns a `TmuxReading`: `located`, `absent` (the script exits 3: `$TMUX_PANE` is unset or the pane's tty is not this process's tty, which is a confirmed mismatch), or `unknown` (any other exit, executor rejection, malformed output, timeout, abort, or a missing `ctx.shell`). The shell script keeps exit 1 for its own failures (`ps` or `tmux display-message` failing) so an unreachable tmux server is `unknown`, never `absent`.
- `packages/context/tmux-context/src/index.ts:apply` - the pre-step listener appends a marker reading only when a previous durable reading exists: `absent` appends it unless the previous state already is the absent marker, and `unknown` appends it only while the previous state is a real location (an `absent` or `unknown` marker already tells the model it has no valid location). A marker uses the same source kind and `tmux location (turn N):` preamble, so the projection stores its body as the state; a later successful location therefore never equals the previous state and is published fresh even when it matches the pre-outage location. A session with no previous reading stays a no-op, as documented.

## The location query has its own deadline (finding 299)

- `packages/context/tmux-context/src/index.ts:queryTmuxLocation` - the query inherited only the turn signal and the executor's general foreground timeout (120 s for bash-local), so a stalled `ps` or tmux server held the first model request. The whole query now runs under `queryTimeoutMs` (default 5000, positive safe integer, validated at load): it is passed to the executor as `timeoutMs` and as an `AbortSignal.any` of the turn signal and a timeout signal so the subprocess is killed, and the wait is also raced against that signal so an executor that ignores it cannot hold the turn. A timeout reads as `unknown`, which is logged as a warning. The turn signal aborting is not a failure: nothing is appended for a cancelled turn.
- `packages/context/tmux-context/src/index.ts:Config` - `queryTimeoutMs` is the new optional field.
