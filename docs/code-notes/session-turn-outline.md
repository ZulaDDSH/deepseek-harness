# session-turn-outline code notes

`packages/session/session-turn-outline/src/projection.ts:OUTLINE_ENTRY_LIMIT` (finding 163): every turn boundary, prompt fill and settled response copied the whole accumulated `turns` array, pushed the complete array on the change feed (control stream and history projection frames), and was cloned into every checkpoint row, so total copied, transmitted and persisted data grew quadratically with the turn count. Chunking the fold state would only have fixed the in-memory copies; the wire value and the checkpoint row would still have held every entry. The fold state itself is therefore bounded to the newest `OUTLINE_ENTRY_LIMIT` (500) entries: `turn/start` appends and drops the oldest entry once the window is full, `stateSchema` rejects a persisted row with more entries than the window, and `stateVersion` is 3 because a v2 checkpoint holding more than the window plus a suffix replay would no longer equal a full replay (both now yield the newest window). The wire value stays a plain array so existing consumers keep working. Turns older than the window have no outline entry: the oldest retained entry's `seq` is the page-back target, and an older turn becomes a rail mark only once history paging has loaded it. A paged outline read (a session-controller history method beside `events`, reading `turn/start` seqs from the log with the same fold and a scan budget) and the matching ui-chat rail hookup are not part of this package; they need a remote API addition and catalog regeneration outside it.
