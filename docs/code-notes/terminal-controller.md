`packages/api/terminal-controller/src/client/model.ts:TerminalView::rename` (finding 270): a rejected rename went through the general failure handler, which set the whole view to failed and non-writable even though the process and attachment were still running, so a cosmetic title failure interrupted typing until the user reconnected. A rename failure now only records its message on the view `error` and leaves the phase, writable flag and attachment alone; a `terminal/unavailable` rejection still fails the view because the terminal is gone, and a rename that settles after the view stopped changes nothing.
