# ui-plugin-manager code notes

## packages/client/ui-plugin-manager/src/client/manager-store.ts:settled

Findings 261, 262, 263, 264. The Gateway client throws before its carrier-error handling when no Connection service exists at dispatch, so the install start (`startInstall`), recovery (`reconcileInstall`), cancellation (`sendCancellation`), version lookup (`checkVersions`) and update (`runUpdate`) calls could reject instead of returning an error result. Each only handled the returned-error branch, so a rejection left `replyLost` false (recovery refused to run), `recovering` true (every later check returned early), the version check `checking`, the dialog `cancelling` and the update `running`. `settled` turns a rejection into a returned failure carrying its message, so each thrown call joins the existing uncertain-outcome branch: the install is marked reply-lost and reconciled by its original request id, a failed recovery clears `recovering` and stays retryable, a failed lookup settles as a retryable refusal, a failed cancellation is retryable, and a failed update shows the lost-result message. No duplicate installation starts because the original request identity is kept. Results are not tagged with a package/version generation beyond `dropStaleVersions` (limit).
