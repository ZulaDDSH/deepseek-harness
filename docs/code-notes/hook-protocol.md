# hook-protocol code notes

`packages/experimental/hook-protocol/src/matcher.ts:hasNestedRepetition`: matcher patterns run through the Host's backtracking `RegExp.test` synchronously, so a valid pattern such as `(a+)+$` against a repetitive 64-character tool name that does not match can burn CPU for far longer than any hook timeout before the hook starts (finding 226). No linear-time engine is installed and dependencies cannot change, so patterns whose group both contains an unbounded repetition and is itself repeated are rejected by `matcherDiagnostic` and never match at runtime. This is a conservative structural check for nested unbounded repetition; it does not detect every super-linear pattern, for example overlapping alternations inside a repeated group, so the limit is documented in the bridge READMEs.
