# llm-pi-ai stream code notes

`packages/llm/llm-pi-ai/src/stream.ts:classifyPiAiError` (finding 41): a message that leads with a 5xx status is classified `SERVER` before any body wording rule runs. The quota, rate-limit, and invalid-request rules scanned the whole message, so a gateway `500 {...upstream invalid_request_error...}` became the non-retryable `INVALID_REQUEST` and a quoted quota error became `QUOTA`. A leading 4xx still lets quota wording win (OpenAI returns quota exhaustion as 429 or 400) and messages with no leading status (`Mistral API error (<status>): ...`, transport text) keep the whole-message scan. A real quota or rate-limit condition reported by a provider with a 5xx status is therefore retried as `SERVER` instead of stopping at `QUOTA`; that is the accepted cost, since the adapter cannot distinguish provenance without structured status.
