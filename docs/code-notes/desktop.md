# desktop code notes

`apps/desktop/src/mandatory-update-policy.ts:DesktopMandatoryUpdatePolicy`: the policy started every process unblocked and was not persisted, so a restart cleared a known mandatory-update block and, when the policy service was unreachable or demanded fresh authentication, the failure preserved the new unblocked state. The constructor now accepts an optional `DesktopPolicyStore`; a mandatory decision (40005) is written to it when received, and the next process seeds its state from it so protected actions stay blocked until a fresh valid no-force response clears the record. The record is bound to the policy origin and the installed bundled dsh version, so an installed update (a different version) or a different deployment ignores a stale record and relies on the launch check. Offline recovery policy: there is none beyond that; an unreachable service keeps the block, and only a fresh no-force response or an installed version change releases it. The file is user-writable and is a durability aid, not a security boundary: deleting it clears the block, as would editing the product itself. Covered by `apps/desktop/tests/mandatory-update-policy.spec.ts`.

`apps/desktop/src/mandatory-update-policy.ts:fileDesktopPolicyStore`: reads tolerate a missing or corrupt file (treated as no record) and writes go through a temporary file and rename; write failures are swallowed because losing persistence must not break the in-process block.
