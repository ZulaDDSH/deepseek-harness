`packages/api/job-controller/src/observe.ts:observeJobOutput` (finding 266): a removal announced during the flush window closed the generation with the removed job projection without reading, and the registry has already deleted the job by then, so output appended after the observer last read was silently dropped while the client treated the status frame as a normal settlement. When the removed projection reports an output total beyond the observer cursor the generation now yields one empty `output` frame with `lossy: true` and `next` at that total before the terminal `status`, which the client records as the existing gap mark. The unread bytes themselves are not recoverable once the record is gone.
