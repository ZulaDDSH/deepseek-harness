`packages/api/job-controller/src/observe.ts:observeJobOutput` (finding 266): a removal announced during the flush window closed the generation with the removed job projection without reading, and the registry has already deleted the job by then, so output appended after the observer last read was silently dropped while the client treated the status frame as a normal settlement. When the removed projection reports an output total beyond the observer cursor the generation now yields one empty `output` frame with `lossy: true` and `next` at that total before the terminal `status`, which the client records as the existing gap mark. The unread bytes themselves are not recoverable once the record is gone.

`packages/api/job-controller/src/client/service.ts:ClientJobs::startRows` (finding 267): a terminal roster stream failure (an end before the first frame, a non-carrier failure, or the shared stream giving up after consecutive carrier failures) dropped the session roster and stopped the entry, and the mounted session header never reacquired a watcher, so running jobs and their stop controls stayed hidden and later jobs never repopulated it. The entry now keeps the roster dropped while it is unavailable (stale rows are not shown as authoritative) and reopens the stream after a backoff of 1, 2, 4, 8, 16 and 30 seconds while any watcher still holds it; a received frame resets the backoff, a release cancels the pending retry, and after the last delay the roster stays dropped until a new watch is acquired. Ordinary carrier reconnects are still handled inside the stream. No distinct failure state is exposed to the UI.
