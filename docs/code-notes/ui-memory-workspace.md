# ui-memory-workspace code notes

`packages/client/ui-memory-workspace/src/automation.ts:MemoryAutomation::withProject` (findings 186, 188): the Memorix server holds one project binding per MCP connection. Automation cached "this workspace is already bound" per `McpHumanOperations` object, but the model-facing `memorix_session_start` tool can change that binding without telling the cache, and a reconnect replaces the server process while the operations object stays the same. Rebinding before every operation is not an option: `memorix_session_start` opens a session row and auto-closes the previous active one, so a bind per document chunk would flood the sessions table. The cache now stores the project id parsed from the bind reply (`Project: <name> (<id>)`). Every store compares the project Memorix acknowledges (`Project: <id>` in the store reply) with that id; a mismatch drops the cache entry, fails that write with a message naming both projects and retries once after a fresh bind. Any other failure of a bound operation also drops the cache entry, and one retry runs when the server's own error asks for `memorix_session_start` (an unbound server after a restart). Search results carry `obs:<id>@<project>`; rows from another project than the bound one are dropped. The mismatch is detected after the write, so the first write after an external switch can still land in the other project and stays there; closing that window needs request-scoped project selection or a connection generation from `packages/mcp/mcp-client/src/human-operations.ts` and is outside this package. A bind reply without a recognizable project line (older servers) disables the comparison and keeps the old cache-only behaviour.

`packages/client/ui-memory-workspace/src/automation.ts:MemoryAutomation::recallFirst` (finding 195): the three-second first-message budget only raced the recall promise, so a recall that was queued behind another Memorix operation still ran its search later, after the chat had already fallen back to recent notes, and a burst of expired recalls delayed saves and imports. `recallFirst` now owns one `AbortController` that aborts when the budget expires; `recallNotes` passes it into the exclusive queue entry, which returns without binding or searching when the signal is already aborted, and into `search` as the caller signal so a search that already started is cancelled. The separate search timeout still starts when the search actually runs. An aborted recall is not reported as a failure because the fallback path already reported the expiry.

`packages/client/ui-memory-workspace/src/automation.ts:SessionTurns::begin` (finding 194): every admitted user message called `begin`, which replaced the stored prompt, so a steering message dropped the original request from the turn digest. `begin` now appends to the messages of the open turn; `finish` and the new `discard` close it. `discard` runs on every `turn/end` that is not `completed`, otherwise an interrupted turn's prompts would be merged into the next turn once messages accumulate. The assistant outcome is still cleared on every admitted message because an answer written before a steer no longer describes the turn. The prompt budget is `PROMPT_CHARACTERS * 2`, shared evenly between the messages (at least 40 characters each, clipped with an ellipsis), joined with ` | Then: `, so the original request and every steer stay visible and truncation is deterministic. The turn title still uses the first 70 characters, which belong to the original request.

`packages/client/ui-memory-workspace/src/client/MemoryPage.tsx:upload` (finding 193): the panel read each selected file with `file.arrayBuffer()` and base64-encoded it before the Host could compare it with `maxDocumentBytes`, so an accidentally selected multi-gigabyte file was fully allocated in the renderer first. `MemoryWorkspace::status` now returns the effective `maxDocumentBytes`, and `upload` compares `File.size` with it before any read; an oversized file is skipped with a localized message naming the file and the limit, and the remaining files still upload. The status is loaded when the page mounts; while it is unavailable (failed status call) the panel has no limit and the Host check remains the only guard. The accepted file is still read whole and sent as one base64 string (at most `ceil(maxDocumentBytes / 3) * 4` characters), because the Remote protocol has no chunked upload; a bounded streaming upload is not implemented.

`packages/client/ui-memory-workspace/src/types.ts:MemoryStatus` (finding 193): carries `maxDocumentBytes`, the Host's effective upload limit, so the panel can refuse an oversized file before reading it. `packages/client/ui-memory-workspace/src/index.ts:MemoryWorkspace::status` fills it from the validated `maxDocumentBytes` config value.

`packages/client/ui-memory-workspace/src/index.ts:MemoryWorkspace::graph` (finding 189): the endpoint took no request signal and its Graphify subprocess only saw the service lifetime, so a client that timed out or unmounted left the rebuild running and every later open or refresh queued another rebuild behind it. `graph` now declares a trailing `AbortSignal`, which the gateway fills with the caller's lifetime (and which also removes the 30 second unary client deadline, so the Host owns the limit). The queued entry starts with `throwIfAborted`, so a rebuild whose caller is gone is skipped without spawning Graphify. `loadGraph` combines the caller signal, the service lifetime and `AbortSignal.timeout(graphTimeoutMs)` into the signal handed to `runNativeCommand`, whose `execFile` kills the child when it aborts; an expiry that is not the caller's own abort is reported as a Graphify timeout naming `graphTimeoutMs`. `MemoryPage` aborts the in-flight graph request when the Context graph tab closes, the panel unmounts or Refresh starts another request. Simultaneous equivalent rebuilds are not coalesced: callers have independent lifetimes, so sharing one run would let the first caller's cancellation cancel the others. Process cleanup is confirmed only as far as `execFile` reports the kill; a child that ignores SIGTERM is not escalated.
