# ui-sidebar-files code notes

`packages/client/ui-sidebar-files/src/client/store.ts:loaded` and `packages/client/ui-sidebar-files/src/client/directory-node.ts:DirectoryNode::read` (finding 219): both retired every previously listed directory that was missing from a new listing, but a listing cut at the Host's entry cap (`truncated`) only shows a prefix, so a directory displaced past the cap by newly added earlier-sorted entries lost its expansion, cached descendants and watch although it still exists. A truncated listing now retires a previous directory only when the listing itself proves it is gone, that is when the same name is present as a non-directory; otherwise its state is kept. `DirectoryNode` keeps its child nodes across listings, so a later complete listing retires them normally. The store replaces the stored listing with the truncated prefix, so when the previous listing was itself truncated `loaded` also considers every level and expansion key below the directory as a candidate, otherwise a later complete listing would never learn about the displaced directory. A directory deleted while its parent listing stays truncated keeps its stale subtree until a complete listing (or the subtree's own failing listing) resolves it.

`packages/client/ui-sidebar-files/src/client/directory-node.ts:DirectoryNode::refreshTree` (finding 216): `follow()` reports a terminal watch error and returns, and `open()` only starts a watch when no task exists, so a node whose watch failed kept a settled task and never observed again while a later successful listing replaced the failure in the display. `follow()` now records `watchFailed` for a non-unsupported failure and `refreshTree()`, which the page reload button and shortcut call, starts a fresh watch before rereading; a restarted watch that fails again is reported through the same `failed` callback, so the degraded state stays visible. An unsupported watch is deliberately not restarted, because it can never succeed. There is no automatic timed retry: a failed watch stays stopped until the user reloads or the node is recreated. Decision for the lead: add bounded automatic retry if reload-only recovery is not enough.
