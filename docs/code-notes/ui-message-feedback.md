# ui-message-feedback code notes

`packages/client/ui-message-feedback/src/client/MessageFeedbackActions.tsx:FeedbackRatingButtons`: clicking a recorded rating used to retract it immediately, and withdrawal is itself an export trigger (a `feedback/message-delete` event authorizes the telemetry backend to release the conversation prefix), so a user removing a rating could send the transcript without being told. The click now opens a confirmation (`withdraw.title`, `withdraw.body`, `withdraw.cancel`, `withdraw.confirm`) that states the release, and only the confirm button calls `retract`; cancelling or closing leaves the rating and sends nothing. The copy is conditional on session telemetry being enabled because the client does not know the Host's live sharing policy: no Remote exposes `sessionTelemetry.sharing` to the browser, so the active policy is not shown. Covered by `packages/client/ui-message-feedback/tests/message-feedback-actions.client.spec.tsx`.

`packages/client/ui-message-feedback/src/client/FeedbackDialog.tsx:FeedbackDialog`: the only disclosure in the dialog was the textarea placeholder, which disappears once text is typed. `dialog.disclosure` is now a persistent note under the category chips naming the scope (the conversation so far), the destination (the configured feedback collector) and the condition (session telemetry enabled), and that withdrawing a rating also exports. Per-message ratings have no local-only form: `feedback/message-put` and `feedback/message-delete` carry no `localOnly` field, so the local-only choice exists only for `/feedback --local` (see `docs/code-notes/command-feedback.md`).
