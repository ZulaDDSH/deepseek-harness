# workspace-changes code notes

`packages/deliverables/workspace-changes/src/store.ts:sessionDirectory`: the old rule kept an id as its own directory name when sanitizing changed nothing, so the ids `.` and `..` resolved to the retention root and its parent, and a 32-bit FNV suffix on sanitized ids let a literal id equal another id's directory name (issues.md finding 73). The rule is now: an id that is a lowercase letter or digit followed by lowercase letters, digits, `.`, `_` or `-` (at most 100 characters, ending in a letter or digit, and not a Windows reserved device name) is its own directory name; every other id maps to `~` plus 32 hex characters of its SHA-256. `~` is outside the literal alphabet, so no literal id equals a hashed name, and uppercase ids hash so two ids differing only in case cannot share a directory on a case-insensitive filesystem. `sessionDirectory` also asserts that the result is a direct child of `root`. Records written under the previous rule are moved lazily by `migrateLegacyDirectory` the first time their id is requested: the previous-rule directory is renamed to the new name when the new one does not exist; ids `.` and `..` are never migrated, and ids that already shared one previous-rule directory (a sanitized id colliding with a literal one) cannot be separated, so the first id to ask takes the directory. Covered by `packages/deliverables/workspace-changes/tests/store.spec.ts` ("session directory").

`packages/deliverables/workspace-changes/src/store.ts:pruneRoot` and `packages/deliverables/workspace-changes/src/index.ts:apply` (`prune`): pruning considered age, count and bytes only, so it could remove the directory of a Session whose recorder was alive, after which the recorder's cached directory creation (`TurnRecorder::scratchDir`) never re-ran and later writes failed (finding 71). `pruneRoot` now takes `isLive`, answered from the plugin's recorder map. Live directories count toward the count and byte bounds first, so other Sessions are evicted to make room, but are never removed; when live Sessions alone exceed a bound, the bound is exceeded rather than a live Session damaged. `isLive` is asked again immediately before each `rm`, so a recorder created during the scan is also spared. A recorder created in the instant between that check and the `rm` finishing is not covered; a Session whose recorder was disposed becomes eligible again. Diff reads of a Session this process did not record (`service.diff` fallback) are not protected and fail as an absent record if the directory is pruned under them. Covered by `packages/deliverables/workspace-changes/tests/store.spec.ts` ("retention") and `packages/deliverables/workspace-changes/tests/plugin.spec.ts`.

`packages/deliverables/workspace-changes/src/store.ts:ensurePrivateDirectory`, `packages/deliverables/workspace-changes/src/capture.ts:captureFile`, `packages/deliverables/workspace-changes/src/store.ts:writeRecord`, `packages/deliverables/workspace-changes/src/git.ts:locateGitWorkspace`: captured copies, records and snapshot objects were created with the process umask, so a traversable custom root with umask `022` exposed a copy of an owner-only source file to other local accounts (finding 74). Every directory this package creates is now made with mode `0o700` and, for an existing directory, narrowed to `0o700` with `chmod` on POSIX; captured copies and record files are written with mode `0o600`. The Session directory is the boundary that protects Git's own object files and subdirectories, whose modes git derives from the umask: they live under a `0o700` parent. The root is created `0o700` only when this package creates it; an existing custom root is not chmod-ed because it may be shared by other tools, and the private Session directories inside it are what hold the content. On Windows the mode arguments are ignored and the stores rely on the inherited ACL of the root (the default root sits under the user's private Harness home); there is no ACL check or repair, and the README says so. Covered by `packages/deliverables/workspace-changes/tests/private-modes.spec.ts` (mode arguments, runs everywhere; real modes, POSIX only).

`packages/deliverables/workspace-changes/src/recorder.ts:TurnRecorder::record` and `packages/deliverables/workspace-changes/src/store.ts:removeRecord`: the recorder appended the `workspace/changes` event and stored the in-memory record first, then wrote the durable record, so a failed write (full or unwritable retention directory) left a card the Client had already been told about and that vanished after a restart (finding 72). The order is now: predict the announcing sequence as `session.seq` (the next event's sequence is always the log length), write the record under that sequence, and only then append. The comparison of `session.seq` with the prediction and the append run in one synchronous step, so no other event can slip between them; when another event was appended during the write the record is removed with `removeRecord` and written again under the new sequence (at most `RECORD_ATTEMPTS` tries, then the attempt fails like a write failure). A failed write appends nothing and stores nothing in memory, so no card exists for that turn: the failure is logged by the recorder's queue, and the next turn is recorded as usual. A recorder disposed during the write appends nothing; its record file stays for retention to remove. A crash between the write and the append leaves a record file no event refers to; it is unreachable and retention removes it with its directory. Covered by `packages/deliverables/workspace-changes/tests/plugin.spec.ts` ("announces no card when the record cannot be written").

`packages/deliverables/workspace-changes/src/git.ts:snapshotTree` and `packages/deliverables/workspace-changes/src/recorder.ts:TurnRecorder::record`: `git add --all --ignore-errors` exits 1 when it skips an unreadable path (stderr names it as `error: unable to index file 'PATH'`, probed on git 2.55 for Windows with an exclusively locked file), and the snapshot accepted that as a complete index, so a skipped path kept its old indexed version or was absent and the turn's summary could omit real changes without saying so (finding 76). `snapshotTree` now returns `{ tree, incomplete, skipped }`: `incomplete` is true for exit code 1, `skipped` holds the paths parsed from stderr (empty when git named none). The recorder keeps the baseline's result and the turn-end result and, when either is incomplete, stores `summary.incomplete = { paths }` (the union, at most `INCOMPLETE_PATH_LIMIT`); the counts stay what the trees show and the flag tells the reader they are a lower bound. An incomplete snapshot with no listed files still announces a card, since a missing card would read as a clean turn. The flag lives in the summary, so it is stored in the durable record and survives a restart. Covered by `packages/deliverables/workspace-changes/tests/git.spec.ts` ("reports the paths a snapshot could not index") and `packages/deliverables/workspace-changes/tests/plugin.spec.ts` ("marks a card incomplete when a snapshot skipped a path").

`packages/deliverables/workspace-changes/src/index.ts:apply` (`workspaceDiff`) and `packages/deliverables/workspace-changes/src/types.ts:WorkspaceChanges::workspaceDiff`: the comparison was addressed by the position of a file in a status list that each request read and sorted again, so a file added, removed or renamed between the client's status read and its comparison request made the same index name a different path (issues.md finding 75). The request now carries the repository-relative `path` of a status entry, and the Host compares the entry of its fresh status whose `path` is equal, so an entry that has since left the status yields `undefined` (HTTP 404) instead of another file's comparison. The path is only matched against the status entries; the file read is built from the matched entry, never from the request string. A path beyond the status list's `maxFiles` cap is not found, as an index beyond it was not. A status generation or opaque token was not added: the path identifies the file, and the client drops its cached comparisons whenever it refreshes the status. Covered by `packages/deliverables/workspace-changes/tests/plugin.spec.ts` ("serves live status and comparisons only for registered Git workspaces").
