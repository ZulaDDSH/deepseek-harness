# session-format-v1-to-v2 code notes

`packages/session/session-format-v1-to-v2/src/migration.ts:transformReleasedEvent` (finding 123): refusing an unknown released-v1 event, including one marked `ignorable: true`, is the recorded alpha decision (`.agents/notes/implemented/architecture/2026-08-31-alpha-historical-unknown-event-refusal.md`): copying an opaque payload cannot prove its sequence numbers survive this seq-remapping edge, and dropping it deletes data. It is not widened here. No first-party v1 writer emitted an ignorable event (the 51 event types in `KNOWN_SESSION_EVENT_TYPES` at `f99b06eaed^` are all in `RELEASED_V0_EVENT_DISPOSITIONS`, and `appendPluginRecord` first landed in `75542dd10a`, after v2), so there is no historical fixture for this shape beyond a synthetic third-party event. The change only makes the diagnostic say that the marker does not exempt the event and that the v1 generation stays unchanged and readable, matching the v0-to-v1 wording. The prefix `format v1 contains unknown event type` is kept because callers and specs match it.
