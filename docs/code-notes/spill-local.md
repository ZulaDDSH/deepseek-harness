# spill-local code notes

`packages/spill/spill-local/src/index.ts:LocalSpillStore` (finding 43): the cleanup sweep ran once at activation, so a long-lived host kept every file that aged past `cleanupPeriodDays` after that sweep. The effect now also starts an unref'd interval (`SWEEP_INTERVAL_MS`, 6 hours; `sweepIntervalMs()` is a test seam) that runs the same `runCleanup` again. Sweeps are chained on `this.cleanup`, so two never overlap, and a tick that arrives while one runs queues behind it; the disposer clears the timer and awaits the chain. The sweep never prunes the active root and already tolerates concurrent writers (a write recreates its session directory), so periodic runs need no extra coordination with live writers or readers. Failures are contained by `sweepSpillRoots` and surface through `ctx.logger.warn`. There is still no size quota: only age bounds retention, so a host that spills more than its disk holds within `cleanupPeriodDays` can still fill the volume.
