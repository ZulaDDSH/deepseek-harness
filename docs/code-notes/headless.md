# headless code notes

## packages/bundle/headless/src/index.ts:run (issue 47)

Background jobs are owned by the run's Agent scope; the jobs registry cancels and awaits them in an owner-scope effect (`jobs.ownerCleanup()`), which appends `job/settled` to the Session. The runner used to request process exit and leave that disposal to application teardown, which can remove Session routing or close the writer first, so the final settlement was lost.

Fix: `run` keeps the `AgentHandle` and disposes it explicitly (memoized `retire`) after the outcome is summarized and before output and exit, on both the success and the failure path, so the owned jobs settle and their records are drained with the Agent's writer. The same `retire` is registered as a plugin teardown effect, so a signal shutdown that disposes the tree while the run is still waiting retires the Agent before the services below it close. The handle comes from `resolveAgent` for resumed Sessions. A failing disposal is reported on stderr and never changes the exit code derived from the task outcome.

## packages/bundle/headless/src/index.ts:awaitGoalContinuation (finding 328)

`packages/bundle/headless/src/index.ts:awaitGoalContinuation`: the one-shot completion loop treated an idle agent with no child work as finished, but the goal-round driver (`goal-round-driver/src/index.ts:awaitingWatch`) deliberately stays idle while a watch job runs and queues the next round on its settlement, so an armed goal could be abandoned with exit code 0. The loop now also holds while `ctx.goals` reports the agent goal `active` and `armed`, waking on `agent/status`, `agent/disposed`, `goal/changed` and `goal/activation-changed` for that agent and re-reading the goal each time. Every driver stop path (pause, block, round limit, error, max-tokens, checkpoint failure, disposal) leaves the goal disarmed or non-active, which releases the wait; a long-running watch therefore keeps the run open until it settles or the process is signalled, and signal shutdown disposes the agent, which releases the wait through `agent/disposed` (an unreadable goal state counts as not continuing). The goals service is optional: without it the loop is unchanged. A composition without the goal-round driver that arms a goal would wait indefinitely, since only the driver disarms; the base bundle always loads it.
