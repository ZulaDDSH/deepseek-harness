# ui-sidebar-documentpreview code notes

`packages/client/ui-sidebar-documentpreview/src/client/excel/xlsx-archive.ts:XlsxPreviewArchive`: `unzipSync` used to expand every entry before any limit ran and returned an object keyed by name, so a highly compressible archive could allocate far beyond the source-byte cap and two entries with byte-identical names silently collapsed to the later one (findings 212 and 215). The constructor now passes a `filter` that sees each central-directory entry before it is decompressed, throws `tooLarge` when the entry count, a single declared size, or the cumulative declared size exceeds `XlsxArchiveBudget`, and throws on any exact or ASCII case-equivalent duplicate name. fflate allocates exactly the declared `originalSize` as the output buffer and does not grow it, so a header that understates the real size cannot enlarge the allocation. The budgets are fixed defaults (2048 entries, 64 MiB per entry, 128 MiB expanded) rather than configuration; they bound allocation but XML structures inside an accepted worksheet are still parsed by ExcelJS.

`packages/client/ui-sidebar-documentpreview/src/client/excel/xlsx.ts:convertXlsx`: an `ExcelPreviewError` raised by the archive budget keeps its `tooLarge` code instead of being rewrapped as `invalid` (finding 212).

`packages/client/ui-sidebar-documentpreview/src/client/html/pack.ts:escapesDirectory`: interactive preview packs declared dependencies into the iframe where page scripts can read the Blob bytes and send them to a remote endpoint, so a crafted page naming `../secret.js` could deliver another readable workspace script (finding 213). References that climb above the document's own directory, including percent-encoded and backslash forms, are no longer read or packed. Dependencies inside the document directory are still delivered to scripts that can use network access; closing that needs a per-document trust prompt or an exfiltration-blocking policy, which is a product decision recorded in the findings report.
