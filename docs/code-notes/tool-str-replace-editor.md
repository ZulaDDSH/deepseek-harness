# tool-str-replace-editor code notes

`packages/fs/tool-str-replace-editor/src/index.ts:insertInFile` (finding 313): the file is split on LF and the pieces are joined with LF again, so in a CRLF file the carriage return belongs to the piece before each LF. Inserted lines therefore take a trailing CR only when another piece follows them. When the insertion lands after the last piece (zero-based boundary equal to the piece count) the old final piece is terminated with a CR if it does not already end in one, and the last inserted line gets no CR, so the join never produces a bare LF separator or an isolated final CR. The boundary range, including the phantom empty piece after a final newline, and the LF behaviour are unchanged: appending after the phantom piece of `one\n` still yields a blank line before the new text, now with CRLF separators for a CRLF file.

`packages/fs/tool-str-replace-editor/src/index.ts:matchOffsets` (finding 316): the scan advances one character after each hit instead of the search length, so overlapping occurrences (`aa` in `aaa`) are all reported and `str_replace` rejects them as `FS_AMBIGUOUS_EDIT` with every starting line. The replaced span is still the single reported match, so no replace-all semantics are involved.

`packages/fs/tool-str-replace-editor/src/index.ts:listDirectory` (finding 314): the two-level traversal spends one shared row budget (`remainingRows`, a quarter of `maxOutputChars`, enough rows to fill the output at the shortest realistic row length) and stops visiting directories and collecting rows once it is spent, then appends a one-line notice that the listing stopped. Directories are still visited in the order `ctx.fs.listDir` returns, so the kept rows are deterministic for a given backend; the final sort runs only over the kept rows. A single `listDir` call still materialises one whole directory because the filesystem service has no paged listing, so one very wide directory costs one backend call; many child directories no longer multiply that work past the budget. When the listing is cut short the rows kept are the first ones in traversal order, which can differ from the first rows of the fully sorted tree for names containing characters that sort before the path separator.
