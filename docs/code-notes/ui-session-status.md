# ui-session-status code notes

`packages/client/ui-session-status/src/client/acknowledge.ts:installReadingAcknowledgements` (finding 305): sending an entry `read` clears the `entered` intent and records `attemptedTurn` before the Host answers, so a failed request used to leave neither a retry path for the manual-clear action nor a trigger when the completion was already read. The failure handler now restores `entered` for the same Session when the request was a clearing one, the Session is still the selected one, no newer entry replaced the intent, and the reading record is still the very object the request was made against. The identity check is the protection for newer manual marks: every committed Host change replaces the record, so a user's explicit mark or a new completion that arrived while the request was in flight makes the record differ and the intent stays cleared instead of overriding that later action. A Host update that shows the reminder already cleared settles the restored intent through `settleEntry`, which also covers an uncertain transport outcome where the Host applied the read. `attemptedTurn` stays set after a failure, so the retry waits for the next focus or visibility event instead of looping on a persistent failure; the console error remains the only failure surface.
