# ui-reference code notes

`packages/client/ui-reference/src/client/index.ts:boundedLookup` (finding 237): the `@` source awaited the file and Session lookups together, so a lookup that never settled while the carrier stayed connected withheld the other domain's finished matches until the query was superseded. Each lookup is now raced against `REFERENCE_LOOKUP_WAIT_MS` (3 seconds) and counts as empty when it does not answer in time, so the working domain always shows; a rejected lookup still rejects the whole query as before, and the query signal and generation checks in `source.candidates` are unchanged. A Remote failure is still shown as an empty domain: the trigger menu contract (`InputTriggerCandidate` in `ui-input-trigger`) has no error or retry row, so surfacing a recoverable error needs a menu-contract change and is left as a decision for the lead. The timed-out request is not cancelled until the query is superseded.
