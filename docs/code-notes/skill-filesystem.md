# skill-filesystem code notes

`packages/skill/skill-filesystem/src/index.ts:readSkillText` (finding 42): every skill file (SKILL.md, flat skills, the `agents/openai.yaml` sidecar) is read through `readSkillText`, which had no byte bound, so discovery and `get` read whole multi-megabyte files. A file larger than `MAX_SKILL_FILE_BYTES` (1 MiB) is now ignored with a warning, the same way a malformed skill is, so one oversized file cannot hide its siblings. The trusted-host path opens the file and reads at most the limit plus one byte, so a file that grows after a check is still bounded. The `ctx.fs` path checks `stat().size` before `readText`; the `FileSystem` seam has no bounded text read that keeps `FS_NOT_TEXT` semantics, so a provider that reports no size, or a file that grows between stat and read, is bounded only by that provider's own limits. The limit is a constant, not configuration, and there is no aggregate catalog budget: the catalog holds frontmatter fields rather than bodies, so the bound that matters is per file. The model-facing body cap belongs to `tool-skill`, which this package does not own.
