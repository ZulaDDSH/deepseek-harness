# session-checkpoint-policy code notes

`packages/session/session-checkpoint-policy/src/index.ts:apply` (finding 176): the policy flushed before each model request, before each top-level tool body, and at `agent/pre-step`. When a step ended the turn the loop broke out without another pre-step, so the final assistant message and `step/end` stayed in the JSONL writer's batching buffer while `turn/end` was appended and completion was reported; a hard crash in that interval lost an answer the user had already seen. The loop dispatches the serial, awaited `agent/turn-stopping` event after `step/end` is appended and before `turn/end`, so the policy now also flushes there, making the final response and step ending durable before the turn is closed. Two windows remain and are documented in the README: the `turn/end` record itself is appended after that barrier (a crash then restores a turn with a durable answer but no ending record), and a turn that ends by error or abort does not dispatch `agent/turn-stopping`. Closing them needs a hook in `packages/core/agent-loop/src/agent.ts` after the `turn/end` append, which this package does not own.
