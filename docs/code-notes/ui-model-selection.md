# ui-model-selection code notes

`packages/client/ui-model-selection/src/client/directory.ts:ModelDirectory.select` (finding 220): the generation counter only suppressed the local settlement of an older response, while its `selectModel` request still reached the Host, so a delayed earlier choice could be applied after a later one and become the durable selection. Selections of one Session are now sent one at a time: a later choice waits for the in-flight request, and a choice that a newer one replaced before it was sent is dropped, its caller resolving as accepted because the newer choice supersedes it. With nothing in flight the request is sent synchronously. `resetConnected` and `dispose` abandon the wait so a request that never settles cannot block later choices. This orders only the choices of one browser client; two clients, or two tabs, selecting at the same time still reach the Host in network order, and the Host has no request sequence or revision to reject the older one. Decision for the lead: a Host-checked sequence would need a new field on `SessionSelectModelRequest` and a per-Session counter in `SessionCommandController::selectModel`, and is left undone.
