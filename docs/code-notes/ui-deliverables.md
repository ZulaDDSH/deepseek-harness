# ui-deliverables code notes

`packages/client/ui-deliverables/src/present-open.ts:handleChangesSummary`, `packages/client/ui-deliverables/src/changes.ts:isChangesSummary` and `packages/client/ui-deliverables/src/client/ChangedFiles.tsx:ChangedFiles` and `packages/client/ui-deliverables/src/client/Deliverables.tsx:Deliverables`: the summary route serves a fixed field list, so the Host's `incomplete` marker (a snapshot skipped unreadable paths, issues.md finding 76) is added to that list and to the client validator as an optional `{ paths: string[] }`. An incomplete summary is drawn with the `changes.incomplete` title instead of the plain count, and `ChangedFilesDock` shows a card for an incomplete summary even when it lists no file, so a partial review never looks like a clean one. Covered by `packages/client/ui-deliverables/tests/changes-open.host.spec.ts` and `packages/client/ui-deliverables/tests/deliverables.client.spec.tsx`.

`packages/client/ui-deliverables/src/present-open.ts:handleWorkspaceDiff`, `packages/client/ui-deliverables/src/changes.ts:workspaceDiffUrl`, `packages/client/ui-deliverables/src/client/workspace-diff.ts:WorkspaceDiffStore`, `packages/client/ui-deliverables/src/client/host-read-store.ts:HostReadStore`, `packages/client/ui-deliverables/src/client/SourceChangesPage.tsx:SourceChangesPage` and `packages/client/ui-deliverables/src/client/WorkspaceChangesTab.tsx:WorkspaceChangesTab`: the workspace comparison route, URL, cache key and both pages addressed a file by its index in the status list, so a status change moved the index onto another file and a refresh left the old comparison cached (issues.md finding 75). The route reads the `path` query (400 when empty), the URL and cache key carry the path, and both pages select a file by path, falling back to the first entry when the selected path left the status. `WorkspaceDiffStore::forget` drops every cached comparison of one Workspace and `refreshStatus` calls it before re-reading the status, so a refresh also refreshes the open comparison. `HostReadStore` gives each read of a URL a token and publishes only the newest one, so a read that was in flight when its URL was forgotten or refreshed cannot overwrite the newer state. Comparisons stay cached between refreshes, as before: edits made after the last status read show only after a refresh. Covered by `packages/client/ui-deliverables/tests/workspace-changes.client.spec.ts` and `packages/client/ui-deliverables/tests/present-open.host.spec.ts`.
