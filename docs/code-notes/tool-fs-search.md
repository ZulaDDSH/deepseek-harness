# tool-fs-search code notes

`packages/fs/tool-fs-search/src/glob.ts:applyGlobTool` and `packages/fs/tool-fs-search/src/grep.ts:applyGrepTool` (finding 133): both tools take the subprocess seam's already-decoded stdout, so they cannot call `readRipgrepLines` and its `undecodable` counter. A file name that is not valid UTF-8 therefore showed up as a path with U+FFFD in `glob`, and as a hard `SEARCH_FAILED` ("no path text") in `grep` because `rg --json` sends the path as base64 `bytes` instead of `text`. `glob` counts listed paths containing U+FFFD (the only signal left after decoding; a real name with U+FFFD is counted too, which the note words as "or contain U+FFFD"). `grep` decodes a `bytes` path with replacement and counts it, and also counts a matched line sent as `bytes` (its preview stays the existing placeholder). Both return an optional `undecodable` count in the result value (omitted when zero) and `packages/fs/tool-fs-search/src/search-core.ts:undecodableNote` appends one note line to the rendered text, in the inline result and in the over-cap rewrite of `tools/post-execute`. The search card `presentationMeta` is not extended, so the card still shows the replaced names; the note is in the model-facing and `tool/result` text. Covered by `packages/fs/tool-fs-search/tests/tools.spec.ts` ("non-UTF-8 names").
