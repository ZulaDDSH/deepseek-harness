# subprocess code notes

`packages/subprocess/subprocess/src/index.ts:SENSITIVE_ENV_PATTERN`: the scrub matched only `KEY`, `PASSWORD`, `SECRET` and `TOKEN`, so `*PASSPHRASE*`, `*PASSWD*`, `*CREDENTIAL*`, `DATABASE_URL`, `*CONNECTION_STRING*` and `*_DSN` reached every child that starts from `scrubbedParentEnv`. The pattern now names them. `AUTH` is deliberately not matched, because `SSH_AUTH_SOCK` is a socket path that git over SSH needs. `scrubbedParentEnv` also removes the `user:password@` part of any `scheme://` value restored from the proxy overlay (`stripUrlUserinfo`), because proxy URLs carry credentials the name filter cannot see; a child that must authenticate to a proxy receives the credentials through the spec's explicit `env`, which merges after the scrub. The scrub stays a name heuristic: an allowlist for untrusted children is a larger policy change, and the README says so.

## Bounded provider disposal (finding 148)

- `packages/subprocess/subprocess-local/src/index.ts:LocalSubprocessRuntime::disposeManagedProcesses` - waiting for a handle's direct result and `waitForExit()` (and for a terminal's `terminate()`) was unbounded, so a child stuck in uninterruptible kernel I/O after an accepted `SIGKILL` kept provider and Host teardown pending forever. Each wait now has a deadline of the spec's `graceMs` plus `DISPOSAL_SLACK_MS`, capped at the timer maximum. On expiry it rejects with `SubprocessError` code `SUBPROCESS_CLEANUP_UNCONFIRMED`; the handle stays in `live`/`terminals`, so the synchronous host-exit path (`terminateForHostExit`) still owns it and shutdown never claims quiescence. The existing failure branch already re-runs `terminateForHostExit()` and throws the error (a single failure is rethrown, several become an `AggregateError`).
- `packages/subprocess/subprocess-local/src/index.ts:LocalSubprocessRuntime::graceOf` - the per-handle grace is recorded at spawn (`spawn`, `spawnTerminal`) in a `WeakMap`; a handle without a record (test doubles) uses only the slack.
- `packages/subprocess/subprocess/src/error.ts:SUBPROCESS_ERROR_CODES` - gains `SUBPROCESS_CLEANUP_UNCONFIRMED`. Waits inside a single handle (`linux-scope.ts:SystemdScopeOwner::waitForExit`, the direct-kill settlement join) stay unbounded on purpose: callers that hold the handle can still observe it later, and only teardown needs a deadline.

## Spill directory is recreated after external removal (finding 104)

- `packages/subprocess/subprocess-local/src/output.ts:privateSpillDir` - the per-process directory was cached forever, so a temporary-file cleaner that removed it while empty made every later spill open fail until restart. It now re-checks that the cached path is still a directory on each `prepareManagedProcessBinding` call (one per spawn) and otherwise creates a fresh `mkdtempSync` directory (random name, mode 0700, exclusive), keeping the original private-creation guarantees; the exit hook removes whichever directory is current. A directory removed between that check and a stream's first overflow still degrades that one stream to its in-memory tail with the logged failure, and the next spawn recovers. SSH helpers use the same function (`packages/ssh/ssh/src/helper-processes.ts`), so they recover the same way.

## Incremental reads hold back an incomplete UTF-8 tail (finding 138)

- `packages/subprocess/subprocess-local/src/output.ts:OutputCollector::readFrom` - the delta was decoded from a raw byte slice and `nextOffset` advanced to `total`, so a poll landing inside a multibyte character emitted U+FFFD for the prefix and the next read decoded the remaining continuation bytes alone. While the stream is open the read now stops at the last complete character (`completeUtf8Length`) and returns `nextOffset` at that boundary, so the held-back bytes lead the next read. Once `seal()` has run (the stream ended) the whole slice decodes, so genuinely malformed final bytes still surface once as replacement characters instead of being withheld forever.
- Not changed: a `lossy` read starts at the retained window, which can begin inside a character; that is the documented truncation boundary and still decodes with a replacement. `readFrom` returns an empty delta while only an incomplete prefix exists, so pollers (`bash-local` readers, `jobs-local` pump) need no change.
