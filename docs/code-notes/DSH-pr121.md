
## packages/todo/tool-todo/src/index.ts:apply — stale todo reminder

`todo_write` only stores the statuses the model sends, so a model that works without calling it leaves the panel stale. `apply` counts non-`todo_write` tool calls per agent (`callsSinceWrite`); every `STALE_AFTER_CALLS` (6) calls while the `todos` projection still has an unfinished item, it appends `STALE_REMINDER` through `tools/post-execute` `additionalContexts`. A `todo_write` call resets the count. The message reuses the `repeat-tool-reminder` source kind (as `subagent/src/step-budget.ts` does) because a dedicated kind needs Session format 5.

## Auto responder

Anchors: `packages/api/session-controller/src/auto-responder.ts:installAutoResponder`, `packages/api/session-controller/src/auto-responder.ts:autoResponderMessage`, `packages/api/session-controller/src/subagent-setup.ts:subagentSetupSchema`, `packages/client/ui-memory-workspace/src/automation.ts:MemoryAutomation`.

- `installAutoResponder` keeps per-session state incrementally from `session/event` (no history reads): the last `assistant/message` text (`answer`, cleared at `turn/start`), the last real user prompt (`request`), `driven` (a `user` message was claimed since the last `turn/end`, so hook or background wakes are never reviewed) and `endedTurn`, set by a `completed` driven `turn/end` and cleared by `turn/start` or any `user/message`. On `agent/status` `idle` it reviews only when the governing setup (`effectiveSubagentSetupOf`) has `autoResponder.enabled`, the session is not a subagent child, `endedTurn > reviewedTurn` and the turn produced agent text. `reviewedTurn` stops one turn being reviewed twice (idle also follows maintenance such as compaction).
- The reviewer is one auxiliary `ctx.llm.stream` call on the session's own model route (`routeOf`), framed as JSON (`userRequest`, `agentLastMessage`) so message text cannot break the prompt. It answers with the next prompt or exactly `DONE`; `autoResponderMessage` maps empty/`DONE` to "send nothing".
- The reply is sent with `agent.followup` as a plain `{ kind: 'user' }` message with no `rpcId`. `auto-review` treats a `user` message with an `rpcId` as a human instruction for permission decisions, so an auto reply must never carry one; the sent message ids are kept in `ids` so a real user message (anything else) resets the counter and replaces `request`.
- Loop guard: at most `AUTO_RESPONDER_MAX_REPLIES` auto replies per real user prompt. A new real `user/message` resets the count and aborts the in-flight review (`state.review`); so does agent disposal. A review also drops its reply if the turn, the agent's idle state, the agent registration or the enabled setting changed while the model answered. Both JSON fields are marked untrusted in `SYSTEM` because the agent text can quote web or file content; abort handles are never cleared, since aborting a finished review is a no-op.
- Memory lookup: `generate` loops. If the reviewer answers `MEMORY: <query>` (first line), it calls the `memory/lookup` waterfall event (`packages/core/agent/src/runtime-types.ts`) and re-asks with the result appended to the `memory` array of the JSON payload, at most `MAX_MEMORY_LOOKUPS` times; a blank query or a third request sends nothing. `session-controller` cannot import the Memorix client, so `MemoryAutomation` (`packages/client/ui-memory-workspace/src/automation.ts:MemoryAutomation.lookup`) answers it with the same project-scoped `search` as first-message recall (this chat excluded, serialized by `exclusive`) and falls through (`undefined`, shown to the reviewer as `no notes found`) for subagents, sessions without a workspace, CLI terminals, empty results and store errors. Notes are marked untrusted in `SYSTEM`.
- Failures only log a warning; the session is left untouched. The reviewer is told never to approve a push, merge, deletion or purchase.
- Schema: `autoResponder: { enabled }` is optional beside `gsd` in `SubagentSetup`, stored per session (`runOptions`) or as the global default, so the setting works with or without subagent mode on.
