# chunked-list code notes

packages/util/chunked-list/src/index.ts:appendChunkedList (finding 346): the list was a linked chain of 64-value nodes whose `previous` links nested one level per 64 values, so a long-lived append-only list produced checkpoint state nested thousands of levels deep; `structuredClone` of the projection state failed at about 1,270 nodes (roughly 81,000 values) and `JSON.stringify` at about 4,800 on this runtime, and the recursive Zod schema validated at the same depth, so one oversized catalog stopped the generic checkpoint clone and the cache write for every projection of that session. The list is now a base-64 counter of immutable blocks: `tail` holds the newest 0 to 63 values, and `blocks` holds complete blocks oldest first, a block being 64 values (height 0) or 64 blocks one level lower (height n), with each height present at most 63 times and heights never increasing toward newer blocks. Appending copies at most the 64-value tail; the 64th value seals the tail into a height-0 block and equal-height runs of 64 blocks merge into one block a level up, so nesting is bounded by the height (at most `MAX_HEIGHT`, enough for 64^9 values) instead of the length, while older blocks are still shared by reference between versions. `chunkedListSchema` validates the block shape, the exact 64-wide blocks, the descending heights and the per-height count, and `iterateChunkedList` walks blocks oldest first and then the tail. The checkpoint shape changed, so projections storing it must bump their `stateVersion` (the subagent catalog went from 6 to 7); an older row is not read and the state is rebuilt from the session log.
