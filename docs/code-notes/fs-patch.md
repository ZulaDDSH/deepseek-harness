# fs-patch code notes

`packages/fs/fs-patch/src/apply.ts:applyHunks` (findings 319, 320): after every hunk is located against the original text the replacement ranges are checked for overlap. A later hunk whose matched span intersects an earlier one (identical EOF spans, partial overlap, or an insertion strictly inside a replaced span) now fails with stage `overlap` instead of one replacement silently overwriting the other; touching ranges and insertions at the same index are still accepted. The `@@` anchor line is a search cursor, not a replaced range, so an EOF hunk that re-matches its own anchor line still succeeds. An insertion-only hunk that carries an `@@` anchor but no `*** End of File` marker fails with stage `insertion`, because the pinned upstream behaviour appended it at the end of the file rather than after the anchor, which is silently the wrong place. Unanchored insertion-only hunks and anchored ones marked `*** End of File` still append at the end.

`packages/fs/fs-patch/src/parse.ts:readUpdate` and `packages/fs/fs-patch/src/apply.ts:replacementLines` (finding 321): the parser records one mark per body line in `PatchHunk.marks` (space for context, `-`, `+`). Reconstruction walks the marks, writes patch text only for added lines and copies each context line from the matched file lines, so a context line that matched only after whitespace or punctuation normalisation keeps its original bytes. A hunk without `marks` (built by hand) falls back to the old behaviour of writing the patch's new lines for the whole region. The trailing-empty-line retry drops the same last old-side and new-side entries from the marks that it drops from `oldLines` and `newLines`.

`packages/fs/fs-patch/src/apply.ts:applyHunks` (finding 322): the result keeps the original final-newline state instead of normalising to a terminal LF. Only one terminal empty split element is treated as the file's final newline, so a pre-existing trailing blank line is content and is no longer consumed by an append or by an empty hunk list, and an unterminated file stays unterminated. Empty text and an empty result stay empty and an empty file that receives lines ends with a newline. Appends go after the last content line.

`packages/fs/fs-patch/src/apply.ts:seekSequence` (finding 323): each normalisation pass over the original lines is computed once per `applyHunks` call and reused by every hunk, and every line comparison spends from one shared budget of `MAX_MATCH_COMPARISONS`. Exhausting it fails the hunk being searched with stage `budget` instead of running an adversarial repeated-line search for an unbounded time. The function is synchronous, so the budget (not a cancellation signal) is what bounds how long the Host is blocked; a typical patch spends well under one percent of it.

`packages/fs/fs-patch/src/apply.ts:describeHunkFailure`: one place turns a failure stage into the sentence both `packages/fs/tool-fs/src/patch/preflight.ts` and `packages/fs/fs-local/src/index.ts` show, so the new stages do not read as a plain mismatch.

`packages/fs/fs-patch/src/types.ts:PatchHunk` and `packages/fs/fs-patch/src/types.ts:HunkApplyFailure`: `marks` is optional so hunks built by hand keep working, and `stage` gained `overlap`, `insertion` and `budget`; the same shapes are mirrored in `docs/subsystems/filesystem.md` under Patch syntax records.
