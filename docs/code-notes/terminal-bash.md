# terminal-bash code notes

## Emulator backlog pauses the terminal stream (finding 155)

- `packages/terminal/terminal-bash/src/session.ts:LocalPtySession::updateFlow` - raw PTY chunks were appended to `emulatorBuffer` while the previous emulator write was still pending, and protocol replies chained onto `responseWrites`, with no ceiling on either, so a fast producer could grow memory past the scrollback limits. The session now pauses `terminal.output` when the pending emulator text exceeds `emulatorPauseChars` (twice `scrollbackMaxBytes`, at least 1 Mi code units; 8 Mi at the default 4 MiB scrollback, which keeps a 4 MiB synchronous burst unthrottled) or more than `RESPONSE_WRITE_PAUSE` (1024) replies are unwritten, and resumes it when the emulator takes the backlog or the replies drain. A paused stream stops reading the PTY, so the kernel's PTY buffer fills and the foreground process blocks in `write` instead of the Host buffering. Memory is bounded by one pause threshold of pending text plus the chunk in flight plus the text the emulator is currently parsing. While paused, scrollback and prompt detection also stop advancing; they catch up as soon as the emulator does.
- `close` and the emulator failure path never leave the stream paused (`closing` disables pausing and resumes), because teardown waits for the stream's `end`. A wedged emulator (a write callback that never fires) still stalls the stream, but no longer grows memory.
