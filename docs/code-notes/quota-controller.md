# quota-controller code notes

## A quota read has a deadline and a cancel handle, and its pending entry belongs to one source (findings 295, 297)

- `packages/api/quota-controller/src/index.ts:QuotaController.fetch` - the pending map was keyed only by provider id and a read was released only when the source's own promise settled, so a source or credential lookup that never settled kept its entry forever and every later call joined it, and a read that outlived its source was handed to the next source registered under the same id. The entry now records its target (the built-in provider or the registered source object) and a call joins an entry only when the target is still the current one; a removed provider id answers `Unsupported provider` immediately instead of returning the old read.
- `packages/api/quota-controller/src/index.ts:QuotaController.start` - the whole operation (credential resolution plus the HTTP request) runs under one deadline, `timeoutMs` in `QuotaControllerInternals` (default 30000, longer than the 15 s HTTP timeout so a normal slow response still reports its own error). On expiry the operation's `AbortController` fires, so the `fetch` the source was handed (wrapped to merge the abort signal into each request) is cancelled, and the caller receives a `configured: true, ok: false` result. Credential lookups cannot be cancelled, so a stuck lookup keeps running in the background but its late result is dropped. The cleanup compares the map entry with its own entry before deleting, so an old operation settling late can never remove a newer pending read.
- `packages/api/quota-controller/src/index.ts:QuotaController.registerSource` - the disposer cancels the source's pending read, so callers waiting on it get a `Quota source changed` result at once and the next fetch consults the replacement source.
- `packages/api/quota-controller/src/index.ts:QuotaController.cancelForCredential` - a `credentials/reference-updated` or `credentials/record-updated` event cancels the pending read of every built-in provider that names that reference or record key, so a credential change never presents the previous credential's read as a fresh one. Registered sources are not matched to credential events because their ids are not credential keys; they are invalidated by disposal only (pi-ai re-registers them when the account changes).
- `packages/api/quota-controller/src/index.ts:QuotaControllerInternals` - `timeoutMs` is the whole-read deadline (credential lookup plus HTTP request), default 30000 ms; it is an injectable test and deployment hook, not a settings field.
- `packages/api/quota-controller/src/index.ts:Pending` - one in-flight read: the target it was started for, the shared result promise, and `cancel`, which aborts the signal bound into the source's `fetch` and resolves the result with an unavailable outcome.
