# fs-ssh code notes

## Uncertain-commit outcome for SSH mutations (finding 136)

- `packages/ssh/fs-ssh/src/index.ts:SshFileSystem::mutate` - the five mutations (`writeText`, `editText`, `patchText`, `deleteFile`, `moveFile`) go through `mutate`. A failure that is not a typed `RemoteOperationError` (lost transport, request cancelled after dispatch, malformed or unparsable reply) cannot prove the remote helper did not commit, so it surfaces as `FsOutcomeUnknownError` with `outcomeUnknown = true`. It keeps the previous `FS_IO_ERROR` / `FS_ABORTED` code so existing handlers still match. A typed remote error is a definite refusal and stays a plain `FsError`. An already-aborted signal fails before dispatch and is also a plain `FsError`.
- `packages/ssh/fs-ssh/src/index.ts:FsOutcomeUnknownError` - the shared `FsErrorCode` set lives in `packages/fs/fs` and cannot grow here, so the flag is a property on a subclass; `isOutcomeUnknown(error)` is the check callers use. The peer (`packages/ssh/ssh/src/protocol.ts:SshRpcPeer::request`) cannot tell a frame that never left the process from one that was sent, so a rejected send is flagged too; over-flagging is the safe direction because callers reconcile instead of repeating.
- Reconciliation flow (README): re-read with a fresh `stat`/`readText`, compare against the `FsVersion` the call guarded with (`expected`), and only repeat the mutation when the version still equals the guard. The mutations are never replayed automatically. Stable per-operation receipts would need a helper-protocol change in `packages/ssh/ssh` and are not added here.
