# webworker-runtime code notes

`packages/experimental/webworker-runtime/src/storage/image-gzip.ts:inflateDigestedArchive` (finding 120): the packer names each lazy archive `lazy/<sha256 of the compressed bytes>.tar.gz` (`packages/experimental/webworker-packer/src/pack.ts:packVfsImage`), but the Worker only checked the fetched archive's registered paths and sizes, so a stale or altered chunk with the same paths and lengths mounted as the named version. `inflateDigestedArchive` hashes the compressed bytes with `crypto.subtle` and compares against the digest in the archive name before the gzip member is inflated; `packages/experimental/webworker-runtime/src/worker-host.ts:deferLazyArchives` loads each lazy archive through it. A mismatch, or a name that carries no 64-digit hex digest, rejects the load; `MemoryVfs.fetchArchive` already leaves a failed archive registered, so the next read fetches again. Unlike the base image, a lazy archive is buffered whole before inflation (the digest covers the whole compressed body), which is bounded by the packer's per-chunk size. This binds the archive to the manifest only; the manifest and its origin remain trusted as before.
