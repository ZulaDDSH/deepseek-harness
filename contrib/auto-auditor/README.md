# Auto Auditor

Auto Auditor reviews Git changes while the Harness host runs, including when the sidebar tab is closed. A lead opens a pull request only when the change is necessary or important, using `auditor_open_and_review` to push a local commit, open a Draft PR via host Git credentials, and queue that exact commit for Auto Auditor in one idempotent step. For an existing open PR, `auditor_push_and_review` pushes the pinned commit under an exact-head lease and audits the confirmed revision. A local commit range also works with `auditor_submit`, and local-branch findings stay with the originating lead.

Auto Auditor reads the PR through a matching configured Git remote and pins the reviewed commit. Its verdict and answers appear in the originating chat and in the Auto Auditor review inbox. Ask a question with `auditor_message` or inspect reviews with `auditor_status`. Run requests (`needs_run`) route directly to the originating lead, including when triggered by a PR Fixer repair.

Claude subscription reviews and replies use the review's pinned repository as their workspace. The originating chat can be closed while the reviewer runs.

Open **Review queue** in Master Control for the latest audit on each submitted PR or lead branch. Select a review to open its findings in Auto Auditor. Install the optional GitHub review status plugin and connect the PR repository to add live GitHub status and required checks.

Both review queues show **Waiting on lead** when the lead owes evidence and **With PR Fixer** while a repair session is active. With **Automatic wake** enabled, an idle or closed fixer with unresolved findings gets up to two resume attempts after two minutes of inactivity. Resumes use the same chat and checkout, and skip queued turns, active jobs, cancelled turns, and outstanding evidence requests. Use **Resume PR Fixer** to continue work from Auto Auditor or the PR Fixer inbox. Auto Auditor also retries transient reviewer failures after 30 seconds and 2 minutes. **Needs input** shows the blocker and next step if recovery is exhausted or a configured limit is reached.

Use **Ask lead to run this** to send the full run request to the originating lead, or **Ask lead to fix check** for a current required-check failure. Under **Delivery**, **Bump lead** sends a separate reminder with the review context. Delivery status records whether the request or reminder was sent.

When a lead completes assigned work for a PR with an active PR Fixer, the assignment instructs the lead to call `auditor_reply_fixer` immediately with the verified results and the full commit SHA for any code fix. The Harness sends the completion directly to that PR's fixer chat, and retrying an identical reply reuses its delivery ID.

Open **PR Fixer** directly below **Auto Auditor** in the sidebar to see the repair inbox for PR reviews with changes requested. Each work order displays the PR link, exact starting commit SHA, round counter, Auto Auditor findings, and any reported lead evidence. Configure a profile-wide provider, model, and reasoning effort in **Fixer model** (defaulting to the audit model and effort). **Automatic wake** and **Auto-publish** default to off in new profiles; when enabled, Auto Auditor starts PR Fixer automatically for new PR `changes_requested` verdicts (without waking recursively on repair re-reviews) and mechanically publishes approved repairs back to the original PR branch under an exact-head lease.

Starting a repair verifies that the live PR head matches the reviewed commit, prepares an isolated detached Git worktree at that SHA, opens a per-review repair chat (locked to Full access and hidden from normal sidebar session lists), and sends one handoff with the PR link, starting commit, findings, source review ID, and lead context. While PR Fixer owns a review, leads cannot push to that PR or stage competing fixes. PR Fixer commits repairs locally and submits them with `auditor_stage_fix` up to the repair round limit (default 3 rounds, after which automatic repairs stop and flag the owner). When PR Fixer needs a build, test, or GPU run from the originating lane, it calls `auditor_request_run` directly to the originating lead, which returns results via `auditor_reply_fixer`. After any repair publication (automatic or via Master Control’s fallback `auditor_publish_fix`), Auto Auditor notifies the originating lead with the new PR head SHA so it can fast-forward its checkout; merging remains a human decision.

Lead sessions automatically receive a one-time PR workflow contract via `agent/pre-step`, and Master Control receives change-deduplicated snapshots of Auto Auditor and PR Fixer state (and can inspect the inbox on demand with `auditor_fixer_status`) while staying out of the routine audit/repair/publish loop.

The queue survives a Harness restart. An approval applies to the recorded commit and base. Submit a follow-up after they change. If the remote lacks a test-merge ref, provide the PR’s target branch or base SHA. The review is local to the Harness and uses the configured reviewer model. A dedicated provider, model, and effort can be set in **Reviewer model**.

Run `npm pack` in this directory and add the tarball with `dsh plugin --profile desktop add <tarball>`. This contribution targets the Harness `0.2.2-rc.5` desktop runtime and uses Git on the host’s PATH.
